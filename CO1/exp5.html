Experiment 05

Demonstrating GET and POST Methods Using HTML Forms

Objective: Create two functional HTML forms demonstrating the architectural and security differences between HTTP GET and HTTP POST methods; observe URL changes, query parameter appending, and data payload visibility.

METHOD: GET

Library Catalog Search

Data is appended directly to the URL as key-value pairs (query string). Suitable for search, pagination, and non-sensitive data queries.

GET Characteristics:
  • Appends data: ?query=...&category=...
  • Can be bookmarked & cached
  • Visible in browser history
  • Data length limited by URL restrictions
METHOD: POST

Secure Student Portal Login

Data is packaged inside the HTTP request body payload. The URL remains completely clean and confidential credentials are not exposed in history.

Notice: The URL did NOT change. Sensitive parameters were submitted in the HTTP Body.
POST Characteristics:
  • Data sent in HTTP Message Body
  • Never cached or stored in browser history
  • No restriction on data payload length (supports uploads)
  • Essential for passwords, transactions, and state changes

Key Differences: HTTP GET vs. HTTP POST

Feature HTTP GET Method HTTP POST Method
Data Visibility Data is visible to everyone in the URL address bar. Data is hidden in the HTTP request payload body.
Browser History & Bookmarks Parameters remain in browser history and can be bookmarked. Parameters are never stored in history or bookmarks.
Security Poor security for sensitive data (passwords, PII, payment info). High security for sensitive data transmissions.
Payload Size Limit Restricted by URL length limits (~2048 characters). No inherent size restriction; allows file and media uploads.
Idempotency Idempotent & Safe (reading/fetching data without side effects). Non-idempotent (creates/updates records, triggers transactions).
